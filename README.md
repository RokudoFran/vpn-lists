# vpn-lists

Выборочная IPv4-маршрутизация через AWG на домашнем MikroTik hAP ax³. Списки включают нужные сервисы и целые CDN по осознанному выбору владельца. Это не гарантия отсутствия прямого выхода для каждого домена: классификация зависит от DNS, IP и прямых исключений.

## Состояние выпуска

- `router/tunnel-watch.rsc` — исходник v3 с исправлением `status` → `stopped`, проверенным владельцем на RouterOS 7.24.4. Планировщик — раз в минуту. Проверены старт STOPPED-контейнера и работа scheduler; остальные аварийные сценарии не считаются проверенными.
- `router/vpn-lists.rsc` — прежний установленный обновлятор. Сохранён для совместимости и отката. Его ограничения (90%, нет транзакции и блокировки) ещё действуют до переключения на v2.
- `router/vpn-lists-v2.rsc` — кандидат обновлятора. По умолчанию `applyChanges=false`: скачивание/валидация без изменения DNS и address-list.
- `router/tunnel-watch-v4.rsc` — кандидат watchdog. По умолчанию `allowRecovery=false`: наблюдение без stop/start.
- `router/install-candidates.rsc` создаёт только два новых пассивных скрипта. Не меняет планировщики, старые скрипты, маршруты или контейнер. Права копируются с существующих скриптов; минимизация прав отложена до проверки на устройстве.
- Новый код RouterOS не исполнялся в RouterOS в среде разработки. Python-тесты и статическая проверка не заменяют runtime-проверку. Порядок перехода: [DEPLOYMENT.md](DEPLOYMENT.md).

## Данные и сборка

`services.yaml` + `manual.txt` → `collector.py` → `lists/` и `reports/`.

GitHub Actions: 04:17 МСК, вручную или при изменениях кода/конфигурации. Расписание GitHub может задерживаться. Сборка и публикация разделены: collector выполняется с `contents: read`, запись доступна отдельному publish job без pip install. Публикация отменяется, если main изменилась после начала сборки. Публикуются только ожидаемые файлы данных.

Форматы:

- Старые `vpn_ipv4.txt`, `domains_vpn.txt`, `domains_direct.txt`, `version.txt` сохранены. Их SHA-256 вычисляется как раньше, установленный updater продолжает работать.
- `bundle.json`: один JSON-ответ с `schema=1`, строкой `payload` и SHA-512 **точных ASCII-байтов** payload. В payload три именованных массива старых списков. Роутер v2 проверяет digest перед изменениями. Это проверка целостности, не цифровая подпись и не защита от владельца скомпрометированного репозитория.
- Максимальный bundle — 60 000 байт; при превышении сборка останавливается. Верхние пределы: 5000 сетей, по 1000 доменов, 50 млн IPv4-адресов. Для роста выше лимитов нужен пересмотр формата/ресурсов, force не снимает эти пределы.
- `reports/stats.json` хранит покрытие каждого источника для сравнения новых адресов, а не только количества строк. После миграции первая успешная сборка создаёт baseline по источникам; старые отчёты такого baseline не содержат.
- Временное окно RIPE намеренно сохранено 14 дней, теперь задаётся явно; это историческое покрытие анонсов, не снимок только текущих маршрутов.

## Проверки

- Повторяющиеся ключи YAML запрещены. Boolean — true/false; имена вроде `off` остаются строками.
- Домены нормализуются, вложения и конфликты между политиками запрещены.
- Отсутствие данных у включённого обязательного IP-источника — ошибка даже с force. Domain-only сервисы не обязаны иметь IP-источник.
- Ограничены размеры ответов, количество записей и доля неразбираемых префиксов.
- Контролируется адресное покрытие и его замена по источникам. Изменение агрегации без изменения покрытия не считается churn.
- FORCE разрешает осознанные резкие изменения, но не пустые источники, некорректную схему и ресурсные лимиты. Не включать автоматически при любой ошибке.
- Все выходы готовятся во временном каталоге. Обычная ошибка commit-фазы вызывает компенсирующий откат. `bundle.json` заменяется последним и атомарно как один файл. Полной атомарности legacy-файлов при отключении питания нет.

## Обновлятор v2

Проверяет SHA-512, формат, публичные диапазоны, выравнивание/порядок сетей, уникальность, доменные labels, вложения, размеры и владение установленными объектами. Применяет только при явном включении `applyChanges` в Source; legacy scheduler должен быть отключён.

Сначала добавляет все отсутствующие записи, затем проверяет наличие всего ожидаемого набора и свойства DNS; только после этого удаляет устаревшее. Версия фиксируется после итоговой сверки. Изменений комментариев у неизменных записей нет. Сверка выполняется даже при прежней версии — пропущенные записи восстанавливаются.

Записи `vpn_git` должны принадлежать управляемому набору (`comment=git`); DNS — `comment=git-dns`. Чужие/отключённые/неоднозначные записи не присваиваются автоматически: скрипт останавливается до применения. Смена уже существующего домена между VPN и direct требует отдельной проверенной миграции; текущий кандидат её намеренно отвергает.

При обычной runtime-ошибке выполняются компенсирующие операции для добавленных/удалённых записей. Откат не является транзакцией при отключении питания или ручном завершении job; журнал явно сообщает сбой отката. Нужны резервная копия и проверка результата. Старые динамические DNS/IP/conntrack-состояния не очищаются массово.

Одноразовый `vpnListsV2AllowShrink=true` разрешает намеренное уменьшение более 25%; запрос поглощается в начале попытки. Это не обход остальных проверок. Runtime-статус: `vpnListsV2LastCheck`, `vpnListsV2LastVerified`, `vpnListsV2LastError`, `vpnListsV2Version`. Эти переменные в памяти и сбрасываются после reboot; они не заменяют независимый мониторинг.

## Watchdog v4

Разделяет start остановленного контейнера и stop/start работающего. Повторный start ограничен интервалом 2 минуты, разрушительный restart — 30 минут. Переходные состояния не сбрасываются вслепую. После последнего ожидания stop состояние читается повторно. Ошибка содержит фазу и исходный текст. Частичный ответ ping — degraded; он сам по себе не вызывает restart.

`vpnWatchV4Maintenance=true` приостанавливает работу, но после reboot переменная сбрасывается. Для обслуживания с перезагрузкой отключать scheduler. Проверка маршрута 8.8.8.8 требует единственный активный маршрут main через wg-awg-proxy-1.

Ограничения: цель VPN пока одна — 8.8.8.8; пути WAN-probe полагаются на нынешнюю конфигурацию; DNS/HTTPS/MTU не проверяются. Новые probe-маршруты не устанавливаются до отдельного сетевого теста. При down нужны два наблюдения; WAN recovery получает grace 2 минуты; начальная загрузка — grace 5 минут.

## DNS, маршрутизация и безопасность

Blackhole в to_vpn защищает только уже маркированный трафик. DNS redirect/mangle, shared CDN-IP, DoH клиентов и холодный старт fetch требуют отдельных испытаний. Скрипты этого выпуска не меняют firewall, DNS-серверы, интерфейсы, маршруты или IPv6.

Текущая direct FWD-конфигурация закреплена за 77.88.8.8; нельзя объявлять второй глобальный DNS гарантированным резервом для FWD. На роутере журналы скриптов сейчас пишутся в `vpnscripts.*.txt`; ротация ограничивает размер, но не износ накопителя.

Не публиковать экспорт с ключами, паролями и env контейнера. Репозиторий содержит данные и вручную устанавливаемые Source; скачанные списки не исполняются как скрипты.

## Локальная проверка

```sh
python -m pip install -r requirements.txt
python collector.py --check
python -m unittest discover -s tests -v
python tools/verify_bundle.py
```

Полный сбор: `python collector.py`; намеренный большой diff: `FORCE=1 python collector.py`. Для первой упаковки существующих списков без внешних запросов: `python tools/package_existing.py`. Это **не свежая сборка** и не обновление BGP-данных.

Dependabot предлагает обновления Actions/PyYAML; автослияние отключено. Все PR проходят read-only offline checks. Версии Actions закреплены SHA, PyYAML закреплён версией; полный hash-lock зависимостей пока не внедрён.
