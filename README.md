# vpn-lists

Выборочная IPv4-маршрутизация на MikroTik HOME-AX3 (hAP ax³). GitHub собирает сети и домены. Роутер раз в час получает один пакет данных по HTTPS и сверяет с ним управляемые записи. Порядок восстановления из чистого клона, проверки на устройстве и отката приведён в [DEPLOYMENT.md](DEPLOYMENT.md).

## Что работает на HOME-AX3

| Компонент | Конфигурация |
|---|---|
| Туннель | Нативный WireGuard `wg-vps0`. В таблице `to_vpn` основной маршрут по умолчанию ведёт в туннель, резервный имеет тип blackhole. |
| Скрипт и расписание | `vpn-lists-v2`, планировщик `vpn-lists-hourly`, интервал `1h`, событие `/system script run vpn-lists-v2`. |
| Статические сети | `vpn_git`, комментарий `git`. |
| DNS | Правила FWD с `comment=git-dns` и `match-subdomain=yes`. VPN использует `8.8.8.8` и список `vpn_dns`, Direct использует `77.88.8.8` и список `no_vpn`. Адреса из ответов DNS появляются в этих списках динамически. |
| Клиентский DNS | На `bridge` исключения UDP/53 и TCP/53 в mangle идут перед VPN-маркировкой. Существующий DNS redirect направляет запросы к внешним DNS на роутер. |
| Загрузка пакета | `/tool fetch` использует исходный адрес `192.168.13.1` и проверку TLS-сертификата. Этот адрес соответствует masquerade домашней подсети при выходе через WG. |

20 ноября 2026 года на RouterOS 7.25.1 часовой запуск обработал пакет из [коммита 48776515](https://github.com/RokudoFran/vpn-lists/commit/48776515a376e2cdb9f706a7a2e28e059fc21401). Результат сверки — 867 сетей, 137 VPN-доменов и 34 Direct-домена. После исправления маркировки с ПК подтверждены UDP и TCP ко всем трём адресам DNS (`192.168.13.1`, `1.1.1.1`, `8.8.8.8`) и HTTPS к `efulfillment.autodesk.com` через `wg-vps0`. Эти числа относятся к указанному коммиту. Для следующего восстановления ожидаемые значения записываются в `RELEASE.txt` конкретного комплекта.

## Файлы для восстановления

| Файл | Назначение |
|---|---|
| [router/vpn-lists-v2.rsc](router/vpn-lists-v2.rsc) | Точный текст поля Source установленной часовой версии. Комплект устанавливает его в именованный скрипт. Прямой `/import` этого файла запускает тело в другом контексте. |
| [tools/verify_bundle.py](tools/verify_bundle.py) | Проверяет схему пакета, SHA-512 ASCII-байтов `payload`, побайтовое совпадение трёх текстовых списков и их общий SHA-256 из `version.txt`. Работает без сети. |
| [tools/prepare_restore.py](tools/prepare_restore.py) | Из локальной истории Git формирует три профиля, установщик, проверяющий скрипт и контрольные суммы. Пробный и первый рабочий запуск привязаны к неизменяемому коммиту. Часовой профиль читает `main`. |
| [router/stage-lan.rsc.in](router/stage-lan.rsc.in) и [router/verify-lan.rsc.in](router/verify-lan.rsc.in) | Шаблоны для генератора. На роутер передаются готовые `.rsc` из комплекта. Проверяющий скрипт отдельно читает управляемые таблицы и сравнивает каждую запись с закреплённым пакетом. |

Файлы `router/vpn-lists.rsc` и `router/tunnel-watch.rsc` сохранены для истории. Первый рассчитан на прежние текстовые списки, второй — на прежний AWG-контейнер. Действующая конфигурация HOME-AX3 использует один скрипт и один планировщик.

Часовой скрипт сначала добавляет недостающие записи и проверяет их свойства, затем удаляет устаревшие. Повторный запуск сверяет фактические записи даже при прежнем дайджесте. Чужая запись, дубль или перенос действующего домена между Direct и VPN требуют разбора до применения. При падении числа сетей или одной из групп DNS более чем на 25% действует защита от сокращения. Переменная `vpnListsV2AllowShrink` расходуется при попытке применения. Для наблюдения доступны `vpnListsV2LastCheck`, `vpnListsV2LastVerified`, `vpnListsV2LastError` и `vpnListsV2Version` в RAM.

## Сборка и публикация

`services.yaml` задаёт сервисы, ASN, источники и доменные политики. `manual.txt` содержит ручные IPv4-префиксы. Сборщик использует RIPEstat за 14 дней, списки провайдеров и ручные записи. Он проверяет конфигурацию, пересечения доменных политик, обязательные источники, резкое изменение покрытия и пределы роутера. Лимит пакета составляет 60 000 байт. Покрытие крупных CDN задаётся в конфигурации. Разные сервисы могут делить один адрес, а клиентский DoH может обходить обычные DNS-запросы.

Расписание [collect](.github/workflows/collect.yml) — 01:17 UTC (04:17 МСК). GitHub может начать позже. Также доступны ручной запуск и запуск при изменении перечисленных в workflow файлов. Один job с `contents: write` устанавливает PyYAML 6.x, проверяет конфигурацию, запускает тесты и сборку, сверяет текущую вершину `main` и публикует изменения из `lists/` и `reports/`. Локальные зависимости закреплены в [requirements.txt](requirements.txt). [Dependabot](.github/dependabot.yml) обновляет GitHub Actions, отдельный [workflow](.github/workflows/dependabot-automerge.yml) обрабатывает автослияние подходящих PR.

SHA-512 подтверждает целостность точных байтов данных. Разрешение на публикацию определяется доступом к GitHub. Для контроля свежести полезны оба показателя — время успешной сборки GitHub и `vpnListsV2LastVerified` на роутере.
