# vpn-lists

Автоматически обновляемые списки IP-подсетей и доменов для выборочной маршрутизации через VPN на роутере MikroTik (RouterOS).

Идея простая: через туннель идёт только то, что недоступно напрямую (заблокированные и ушедшие из РФ сервисы, нужные CDN), а всё остальное, особенно российские сервисы, ходит напрямую.

## Как это работает

```
services.yaml + manual.txt
        │
        ▼
collector.py  (GitHub Actions, каждый день в 04:17 МСК)
        │   ├─ проверка конфигурации и ручных записей (без сети)
        │   ├─ префиксы по ASN из RIPEstat
        │   ├─ официальные списки IP CDN (Cloudflare, CloudFront, Fastly)
        │   ├─ ручные подсети, не покрытые автосбором
        │   └─ сравнение с прошлым сбором: резкие изменения останавливают запись
        ▼
lists/*.txt  ──►  роутер MikroTik забирает списки по raw-ссылке (router/vpn-lists.rsc)
```

1. **`services.yaml`** описывает сервисы: ASN, источники IP, свои подсети и домены. Сервис можно выключить через `enabled: false`, не удаляя описание.
2. **`collector.py`** собирает IPv4-префиксы, отбрасывает приватные и IPv6, схлопывает пересекающиеся подсети, убирает лишние поддомены.
3. **`manual.txt`** хранит подсети, добавленные вручную. Всё, что уже покрыто автосбором, скрипт выкидывает сам, а по каждой записи пишет в `reports/manual.md`, насколько её покрывает автосбор и чья она.
4. **GitHub Actions** (`.github/workflows/collect.yml`) гоняет офлайн-тесты и запускает сбор по расписанию, вручную или при изменении конфигов; коммитит результат, только если списки поменялись.

## Выходные файлы

| Файл | Что внутри |
|---|---|
| `lists/vpn_ipv4.txt` | IPv4-подсети для маршрутизации через VPN (одиночные адреса без `/32`, как хранит RouterOS) |
| `lists/domains_vpn.txt` | домены, которые нужно пускать через VPN |
| `lists/domains_direct.txt` | домены, которые всегда идут напрямую (`no_vpn`) |
| `lists/version.txt` | SHA-256 от содержимого списков: роутер обновляется только когда он меняется |
| `reports/manual.md` | ручные подсети: зачем добавлены, сколько покрыто автосбором (100% — можно удалять), AS и владелец |
| `reports/sources.md` | сколько префиксов и адресов даёт каждый источник и какая это доля итогового списка |
| `reports/domains.md` | домены, которые не нашлись в DNS: опечатки и переехавшие сервисы |
| `reports/stats.json` | префиксы и адреса по каждому источнику: с этим сравнивается следующий сбор |

Списки содержат только данные, без команд RouterOS: роутер сам их скачивает, проверяет и применяет.

## Защита от поломок

Сборщик ничего не записывает, пока не пройдены все проверки: обновляется либо всё, либо ничего.

- **Конфигурация.** Неизвестный ключ в `services.yaml` (`domain:` вместо `domains:`, `no-vpn:` вместо `no_vpn:`) или сервис без явного `enabled` останавливают сборку, а не выключают сервис молча. Домены проверяются и приводятся к нижнему регистру; домен сразу в VPN и в `no_vpn` — ошибка.
- **Ручные подсети** (`manual.txt` и `prefixes:`) разбираются строго: опечатка в маске вроде `/2` вместо `/22` даёт ошибку, а не четверть интернета в туннеле; запись шире `/12` или повтор — тоже ошибка.
- **Источники.** Каждый запрос повторяется до 3 раз; если источник недоступен или RIPEstat ответил ошибкой, сборка останавливается. Префикс шире `/8` от источника считается мусором.
- **Резкие изменения.** Если источник отдал меньше половины прошлого числа префиксов, объём адресов изменился больше чем на 25% или доменов стало на четверть меньше — списки не перезаписываются. Если так и задумано (включил или выключил крупный сервис): **Actions → collect → Run workflow → force**, локально `FORCE=1 python collector.py`.
- **Минимум**, который не отменяет даже force: 50 подсетей, 20 VPN-доменов, 5 доменов `no_vpn`.
- **Домены** проверяются на существование через DoH: несуществующие попадают в `reports/domains.md` и предупреждением в Actions. Сборку это не останавливает: сбой DNS не должен мешать обновлению.
- **GitHub Actions** закреплены по хешу коммита, а не по тегу. Раз в месяц Dependabot предлагает новые версии Actions от самого GitHub (не раньше чем через неделю после релиза), workflow `dependabot-automerge` прогоняет на них тесты и сливает PR сам. Если тесты упали или PR трогает что-то кроме workflow-файлов, PR остаётся открытым до ручной проверки.
- **Роутер** проверяет всё ещё раз сам (см. ниже).

## Как добавить сервис

```yaml
services:
  example:
    enabled: true
    asn: [12345]            # префиксы подтянутся из RIPEstat
    prefixes: []            # свои подсети, если своей AS нет (проверяются строго)
    domains: [example.com]  # попадут в domains_vpn.txt, поддомены не нужны
```

ASN перед добавлением стоит проверить на [bgp.he.net](https://bgp.he.net). Допустимые ключи: `enabled`, `asn`, `sources` (`cloudflare`, `cloudfront`, `fastly`), `prefixes`, `domains`.

## Роутер

Код из репозитория на роутере не выполняется: скрипты ставятся руками, а с GitHub роутер качает только данные.

- **`router/vpn-lists.rsc`** — обновление списков (System → Scripts → `vpn-lists` → Source, планировщик раз в час). Проверяет каждую строку, минимумы и что новый список не меньше 3/4 текущего; старые записи удаляет, только если новых легло не меньше 90%. Если список уменьшился осознанно: `:global vpnListsForce true; /system script run vpn-lists`.
- **`router/tunnel-watch.rsc`** — сторож туннеля (планировщик раз в 5 минут): пингует 8.8.8.8 через туннель. Если туннель молчит, проверяет интернет напрямую: нет интернета — это авария у провайдера, контейнер не трогает; интернет есть — перезапускает контейнер AmneziaWG, повторно не чаще раза в 30 минут. В лог пишет, с какого момента был простой.
- Сообщения скриптов (кроме debug) и критические события пишутся на диск в `scripts-log.*.txt` и переживают перезагрузку.

Схема на роутере, которую эти скрипты предполагают:

- таблица `to_vpn` с маршрутом по умолчанию в туннель и blackhole на случай, если туннель пропал: в WAN ничего не утекает;
- mangle: `no_vpn` → accept для новых соединений, выше всего; `vpn_git` и `vpn_dns` → connection-mark → routing-mark `to_vpn`; собственный HTTPS роутера к `vpn_dns` тоже в туннель (так список качается через него); клэмп MSS в postrouting;
- fasttrack только для непомеченных соединений;
- FWD-записи VPN-доменов резолвятся через 8.8.8.8, до которого есть маршрут через туннель; direct-домены — через обычный DNS (Яндекс, запасной — DNS провайдера);
- обычный DNS из LAN заворачивается на роутер, чтобы доменная часть работала и у устройств с прописанным DNS.

Адрес VPS, ключи и параметры обфускации в репозиторий не кладутся.

## Локальный запуск

```bash
pip install pyyaml
python collector.py --check                 # проверить services.yaml и manual.txt, без сети
python -m unittest discover -s tests -v     # офлайн-тесты защиты
python collector.py                         # полный сбор
```
